# Casos de uso y aceptación

UC-01: crear Workspace y Brand; acceso sólo membership; `brand_created`. UC-02: aprobar Customer desde tarjeta con opciones, hipótesis y rationale; una versión y evento. UC-03: modificar Recommendation antes de commit; contenido final humano y fuente de origen. UC-04: rechazar Recommendation; ninguna Decision creada. UC-05: aprobar Positioning dependiente de Customer; arista persistente. UC-06: cambiar Customer; vieja versión consultable, Positioning Needs Review sin reescritura. UC-07: revisar Positioning; resolver ReviewItem con nota humana, mantener audit. UC-08: registrar Experiment, Signal y Learning revisado. UC-09: User trabaja en Brand A y B sin mezclar contexto; Capability Context persiste en User. UC-10: IA/research fuera de servicio; entrada manual/decisión siguen disponibles. Cada caso requiere test y telemetría según [matriz](../00-index/traceability-matrix.md).

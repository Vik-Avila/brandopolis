# ADR-0023 · Prioridad de lanzamiento (GTM Priority) y línea del recorrido

- Contexto: la Decision Spine canónica continúa Core Message → GTM Priority → Priority Experiment
  ([decision-spine](../03-methodology/decision-spine.md)); pregunta aprobada «¿Dónde y cómo debemos
  concentrar inicialmente nuestros recursos?». [Activation Analysis](../05-ai/activation-analysis.md)
  toma Customer, Value Mechanism, Positioning y Message aprobados, advierte que una sugerencia puede ser
  provisional ante upstream en revisión y nunca actualiza GTM automáticamente. Sólo fuera de producción.
- Decisión:
  - GTM Priority es una Strategic Decision versionada con el motor existente (versión, razón humana,
    historial, 409, idempotencia, auditoría, Change Impact). Sin schema nuevo ni migración.
  - `modules.v4.json` la marca como `journey` (08 Prioridad de lanzamiento, última sección);
    `learning-moments.v4.json` usa la capacidad existente GTM Prioritization.
  - Dependencias: se conserva Positioning → GTM Priority (SOFT, v1) y, por decisión del propietario
    (2026-10-06), `dependencies/v4.json` añade Core Message → GTM Priority (SOFT, `ruleVersion: v4`,
    `reviewOnFirstUpstreamVersion`). Una revisión sugerida nunca reescribe GTM ni fuerza NEEDS_REVIEW, y
    la regla de ADR-0022 evita duplicarla (Positioning → Message → GTM). La primera versión de GTM no
    genera impacto (no tiene downstream implementado).
  - Marcas existentes: GTM sólo se agrega con la acción explícita «Agregar estas secciones» (ADR-0021).
  - Orientación local de GTM: si Cliente, Modelo de valor, Posicionamiento o Mensaje están en revisión,
    advierte en palabras que cualquier propuesta puede ser provisional. Brando reutiliza la consulta
    explícita; sin cambios de proveedor, modelo, prompts, schema ni datos enviados.
  - DEMO CoffeePolis: sandboxes nuevos incluyen una prioridad de lanzamiento de ejemplo (patrón de
    ADR-0021/0022); los existentes no cambian.
  - Línea del recorrido: los números de las fases son nodos unidos por una línea vertical; las fases
    decididas rellenan su nodo, la actual conserva su tarjeta y nodo esmeralda, y la siguiente sugerida
    (`nextPhase()`) recibe un doble anillo champán, un pulso finito (3 ciclos) y el texto «Siguiente
    decisión sugerida» en `title`/`aria-description`. `prefers-reduced-motion` elimina el pulso; el estado
    nunca depende sólo del color ni del movimiento.
- Resuelto por el propietario (2026-10-06): Core Message → GTM Priority, SOFT. No se añadieron otras
  aristas hacia GTM; cualquier otra requiere una decisión propia.
- Consecuencias: marcas nuevas con ocho secciones («X de 8»); comparabilidad de métricas según
  [metrics](../09-validation/metrics.md).
- Validación: `tests/gtm-cases.ts`, suites actualizadas y `tests/brando-browser/brando.spec.ts`. Estado
  real en SESSION_STATE.
- Release: sólo fuera de producción; Jury Production Freeze sin cambios. No autoriza commit, push,
  merge, tag, migración ni deploy.
- Revisión: nueva decisión explícita de producto.

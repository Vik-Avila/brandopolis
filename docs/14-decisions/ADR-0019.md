# ADR-0019 · Select Brando proposals before human decision review

- Status: Accepted for the authorized non-production B1 follow-up, 2026-10-05
- Decision owner: Human product owner

## Problem

Showing the first suggestion automatically in the workspace duplicates controls and implies
selection without the strategist choosing it. Generic evidence advice is not a strategic choice.

## Decision

Brando lists actions per suggestion. Human selection of an explicit strategic alternative opens
its exact proposed decision in the existing editable workspace, with an empty human rationale.
Accept/Modify never commit. Final confirmation uses the existing human commit, version history,
practice, source proof and impact workflow described in ADR-0018. Reject remains in the panel.
The workspace shows only the selected suggestion; it has no duplicate Accept/Modify/Reject set.

Schema brando-answer-v2 and prompt brando-contextual-v3 add an optional parallel suggestionActions
array for backward compatibility. Typed STRATEGY requires a current question and a nonempty
proposedDecision. EVIDENCE opens registered evidence; CONTEXT opens context. Missing, mismatched
or incomplete descriptors default to contextual navigation. No language keyword guessing.
The engine binds normalized action metadata into the actor/brand-scoped source ticket and rejects
non-strategic tickets at commit, even if a client fabricates buttons. Model descriptors grant no
write authority. Old v1 schema and v1/v2 prompts remain unchanged. No DB schema or migration.

## Validation and boundary

Regression coverage: choosing the second option, exact selected draft, no pre-confirmation commit,
no workspace duplication, evidence navigation without writes, non-strategy ticket refusal and
safe legacy output. Full Windows database/browser/visual/PILOT gates and human live review remain
required. No production, configuration, infrastructure, commit, push or deploy authorization.

## Review classification correction · 2026-10-05

At final human commit the server compares the confirmed selected option against the
issued proposedDecision, ignoring outer whitespace. A changed choice is recorded as
MODIFY even when the person initially clicked Accept. An explicit Modify remains MODIFY.
This keeps practice and audit faithful to the confirmed action without changing human
authority, versioning, impact or durable idempotency semantics.

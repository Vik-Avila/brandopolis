# ADR-0011 · Runtime M1, persistencia y sesión humana

Resuelve ADR-0003/0004 para M1 sin seleccionar auth de producción. TypeScript estricto, Node 24, pnpm, Drizzle + node-postgres; transporte HTTP nativo mínimo. Sin SDK de IA. PostgreSQL 17 nativo de desarrollo mediante embedded-postgres (herramienta dev, wrapper beta fijado, no motor simulado); DB externa por DATABASE_URL para despliegue futuro. Sin instalaciones de servicios del sistema. Vitest sobre PostgreSQL real y Ajv sobre schemas v1.

| Criterio | Drizzle | Prisma |
|---|---|---|
| Migraciones | SQL generado, fácil extender constraints/triggers | sistema de migraciones y cliente generado |
| Tipos/PostgreSQL | tipos TS e interfaz SQL explícita | cliente tipado y soporte PostgreSQL |
| Transacciones/testabilidad | control directo de locks y SQL, driver pg | transacciones interactivas, abstrae más SQL |
| Mantenibilidad/agentes/velocidad M1 | menos generación de cliente, SQL revisable en este corte | buen modelo declarativo; otra capa para SQL específico |

La preferencia por Drizzle es juicio de implementación, no benchmark. Referencias consultadas: [Drizzle transacciones](https://orm.drizzle.team/docs/transactions), [migraciones](https://orm.drizzle.team/docs/migrations), [Prisma migraciones](https://docs.prisma.io/docs/orm/migrations/how-migrations-work).

Auth M1: puerto de sesión opaca; hash SHA-256 de token aleatorio persistido con usuario, workspace y expiración. Resolver actor server-side; membership activo y asignación Brand por operación. No aceptar actor/workspace del browser como autoridad. Tokens de demo se generan desde CLI local; no registro público, passwords ni proveedor auth nuevo. Servidor sólo loopback y datos DEMO; prohibido activar en producción. Auth final queda abierto antes de piloto. AI/chat no disponen de ruta de sesión humana ni commit.

Commits serializados con lock de Brand (granularidad conservadora M1), optimistic activeVersion y key/fingerprint bajo la misma transacción. Versión+audit+outbox atómicos. Impacto posterior determinista, transaccional e idempotente; errores conservan IMPACT_PENDING y se reintentan explícitamente. No cascade: sólo aristas salientes de la decisión cambiada. Revisión humana exige receipt server-side ligado a versión y conjunto de triggers para impedir cerrar un impacto no visto.

Sesiones CLI/dev son una limitación deliberada para M1. Antes de piloto: proveedor de auth, provisioning, rotación/revocación UI, despliegue, backups y política de retención. El dominio no depende de la forma de login.

# ADR-0013 · acceso de piloto y continuidad de datos

Se conserva HTTP nativo, Engine, Drizzle y PostgreSQL. Login PILOT mediante OpenID Connect Authorization Code + PKCE/nonce/state con openid-client; ver [ejemplo oficial](https://github.com/panva/openid-client/blob/main/examples/oidc.ts). El proveedor administra credenciales, verificación y recuperación; Brandopolis nunca almacena passwords. Issuer y subject verificados se vinculan explícitamente desde CLI a User/Workspace. No auto-link por email, registro público, SSO empresarial ni concesión implícita de permisos.

La sesión de aplicación sigue opaca y server-side, con expiración y revocación; cookie Secure/HttpOnly/SameSite y origin exacto detrás de TLS. La autenticación no reemplaza membership ni asignación. PILOT utiliza DB separada de DEMO y rechaza sesiones sin vínculo OIDC activo. El acceso por token pegado sólo permanece en loopback DEMO. Sin credenciales/issuer/HTTPS configurados, PILOT no arranca.

Provisioning permite crear tester con Workspace propio o asignación explícita a Workspace PILOT. Disable revoca sesiones y membership del tester. Cohorte y clasificación pertenecen a configuración persistida; intervención se registra por sesión. Feedback separado de estado estratégico. Telemetría adicional versionada preserva eventos existentes y no incluye texto estratégico ni tokens.

Migraciones exclusivamente aditivas desde RC1; backup verificado, migración explícita, release de app y readiness. Ningún start/deploy ejecuta seed o recrea DB PILOT. Rollback sólo a app compatible con el schema expandido; RC1 no es rollback de PILOT porque carece de auth pública. Hosting, issuer y credenciales reales siguen siendo configuración externa requerida, no infraestructura inventada.

Continuación 2026-09-25: el cliente puede ser confidencial (OIDC_CLIENT_SECRET) o público con PKCE (OIDC_PUBLIC_CLIENT=true); OIDC_REDIRECT_URI debe ser exactamente PILOT_ORIGIN/auth/callback. Un callback fallido, expirado, repetido o de identidad no provisionada redirige a la entrada con un motivo genérico y nunca emite sesión. El email no se usa como identidad. Límite de solicitudes en memoria por cliente (IP detrás de proxy confiable con TRUST_PROXY=true) y por sesión para IA y feedback; válido para una sola instancia. DEMO y PILOT rechazan al arrancar una base con datos de la otra clase. El apagado local de PostgreSQL usa pg_ctl -w sobre su propio directorio antes de cualquier copia en frío.
